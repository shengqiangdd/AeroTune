# GitHub updater release blockers

**Status (2026-11-01): the base Tauri config remains updater-disabled by default. The owner authorized an early-access v1.5.10 bootstrap release followed by a v1.5.11 GitHub-updater test; a production signing key is configured in the protected `aerotune-release` environment and the repository public-key variable. Release builds enable the updater gates, while the documented cancellation, concurrency, and repair cases remain unverified. The v1.5.10 tag is pinned to the reviewed release commit, but no GitHub Release has been published yet.**

This replaces the earlier SignPath/scheduled-task/ProgramData proposal. The main checkout has Git metadata and an `origin`; the prior statement claiming there was no Git repository or remote was stale. This owner-confirmed source baseline is being frozen in a clean versioned commit; each release tag must point at its exact clean `main` commit.

## Release gates and early-access decision

The base Tauri config remains disabled. The v1.5.10/v1.5.11 release builds use the checked-in updater gates below, which the owner explicitly authorized for early access. This decision does not mean the unrun cancellation, concurrent-launch, interrupted-install, or repair cases passed; those remain called out in the table above and evidence log.

- `UPDATE_FEED_RESPONSE_BOUNDED_READY`
- `UPDATE_PROXY_POLICY_READY`
- `UPDATE_BOUNDED_DOWNLOAD_READY`
- `GITHUB_RELEASE_HOST_POLICY_REVIEWED`
- `GITHUB_RELEASE_WINDOWS_ACCEPTED`

The release preflight derives readiness from those checked-in booleans plus the protected signing overlay; no workflow variable can silently override the source gates. The old custom update-only implementation, recovery module, and task-registration script were removed. The app explicitly exits if an already-registered stale task supplies `--aerotune-update-only`, so it cannot fall through to launching the UI elevated.

## Standard Tauri limitations

The standard updater launches NSIS using the current user's temporary staging area and does not provide AeroTune's prior protected transaction journal or crash-safe rollback. The normal Settings confirmation is UX, not an authorization boundary; the bundled webview can invoke the narrow Rust IPC commands directly. The updater plugin's own JavaScript commands remain unavailable because no updater capability permission is granted.

GitHub's `latest.json` is unsigned metadata. Tauri's Minisign verification and `requireSignedVersion: true` authenticate the release payload/version pair; the feed's other metadata is not independently signed. Downgrades and unsafe TLS options remain forbidden. A valid updater signature is not Authenticode.
