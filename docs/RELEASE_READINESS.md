# AeroTune release readiness

## Verdict

AeroTune has broad Windows-specific functionality and stronger-than-usual safeguards for reversible changes and destructive operations, but it is **not yet ready for general availability**. Treat it as an advanced-user beta until signed distribution, privacy review, accessibility validation, and disposable-VM install/recovery acceptance are complete.

## Practices borrowed from mature software

- **Modular behavior plus tests:** follow [Microsoft PowerToys developer guidance](https://github.com/microsoft/PowerToys/blob/main/doc/devdocs/readme.md): keep features behind clear interfaces and add/update tests with behavior changes. The Windows workflow is configured to run all `scripts/check-*.mjs` contracts plus Rust and frontend checks; hosted execution is still pending.
- **Preview before destructive action:** preserve the review-and-select pattern used by [Windows Storage recommendations](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/free-up-drive-space-in-windows). AeroTune's cleaner already previews categories/candidates before cleanup; keep irreversible deletion distinct and explicit.
- **Least-privilege automation:** follow [GitHub Actions security hardening](https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions): CI has read-only repository permission, SHA-pinned actions, no signing secrets, no publishing permission, and a non-bundling/non-signing Tauri compile.
- **Privacy and diagnostics:** use [PowerToys' privacy documentation](https://github.com/microsoft/PowerToys/blob/main/DATA_AND_PRIVACY.md) as a model for clear data inventory and opt-in diagnostics. AeroTune now previews an allowlisted report and requires separate opt-ins for identifiers and detailed telemetry; the full technical inventory is in [DATA_PRIVACY_INVENTORY.md](DATA_PRIVACY_INVENTORY.md).
- **Accessible names and validation:** follow Microsoft's [Windows accessibility guidance](https://learn.microsoft.com/en-us/windows/apps/develop/accessibility). The disabled suspend control has a contextual accessible name; resume requires confirmation and a process-instance token, and is disabled with an explanation when the row identity cannot be checked. Terminate remains available. Keyboard, Narrator, contrast, and 200% scaling still need real UI acceptance.
- **Trusted distribution:** Microsoft notes the importance of signing for [Smart App Control](https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/code-signing-for-smart-app-control). The current installer is not Authenticode-signed. Tauri's Minisign updater key authenticates updater bundles but does not identify the publisher in UAC; Authenticode remains a separate, optional signing process. See the [Windows signing policy](WINDOWS_CODE_SIGNING.md).

## Improvements in this pass

- Pinned the package manager (`pnpm@11.8.0`) and explicitly allowlisted only esbuild's install build step. A frozen offline install now passes. Removed the stale, divergent npm lockfile; the frozen pnpm lock is the only supported root JS dependency tree.
- Added `pnpm run test:contracts` to discover/run all source-contract checks and `pnpm run check:release` for frontend build, all contracts, Rust formatting, Clippy correctness/suspicious lints, Rust tests, and vendored updater tests. The IPC contract confirms frontend commands match the Rust handler allowlist.
- Added the [Windows CI workflow](../.github/workflows/ci.yml) for PR/push validation with read-only permissions and commit-SHA-pinned actions, plus weekly Dependabot updates for GitHub Actions, pnpm dependencies, and both Cargo projects. CI builds/tests without signing or publishing, and separately compiles the guarded Tauri app with `--no-bundle`.
- Prepared the selected standard Tauri + GitHub Releases updater: fixed HTTPS feed/host policy, Rust-only IPC façade, bounded signed archive verification, passive per-machine NSIS install, generated `latest.json`, and a separate release workflow whose `contents:write` permission is isolated to a publish-only job. The runtime acceptance gates remain false; no key, tag, or release is configured.
- Guarded Tauri build and bundle commands now run the `lib.rs` provenance/IPC contract before invoking the CLI with signing secrets removed; a mismatch fails closed and reports both recorded and current hashes, preventing direct package commands from skipping the source gate.
- Removed plaintext Wi-Fi password export and display. Saved WLAN metadata is loaded only after an explicit click; the backend does not request `key=clear`, parse password fields, or return credential data.
- Added contextual accessible names to icon-only process actions. New process suspension is disabled in the UI and backend; resume now requires an opaque FILETIME token, cross-checks the row's image and second-resolution start time, then verifies the full creation time on the same still-open handle used for `NtResumeProcess`; mismatches fail closed with refresh guidance. The UI displays the exact UTC creation time in a dedicated PID/start-time column, row tooltip, accessible action name, and confirmation; it disables resume when that token cannot be formatted/verified. Manual row termination, priority and affinity changes also require the captured token and verify exact FILETIME on the action handle. On steady scans, the list retains an action token only when exact FILETIME from the previous row snapshot, a current pre-refresh query, and the post-refresh row token all agree; warmup reseeds sysinfo's CPU/I/O baseline after its pre-token capture. Rows lacking stable identity remain read-only and require list refresh. Dashboard anomaly actions open the process row for review rather than mutating directly by PID. When automatic deprioritization is configured, the process inventory captures an internal FILETIME alongside each sampled row; diagnostics carries it without serializing it to the renderer, resets PID tracks on exact-token changes and discards metrics from any coarse/exact identity-transition sample, and both deprio paths use same-handle priority verification, skipping with action feedback when identity is absent or stale. A failed list refresh keeps the prior snapshot visibly stale and disables PID-based row actions until a successful retry; rows without a verifiable creation token are likewise read-only. The previous/pre/post exact-identity check narrows but does not make row sampling atomic; a collision of identical FILETIME values and process-refresh timing still require disposable-VM validation. Automatic FILETIME is still queried adjacent to (not atomically with) sysinfo metrics, but any observed coarse/exact identity transition now discards that scan's process metrics instead of attributing them to the new identity; this capture path remains VM-gated. Diagnostic export now opens an accessible pre-save dialog with a live final-JSON preview; device identifiers and detailed telemetry are omitted by default and require separate opt-ins. Unknown report fields are dropped by an explicit allowlist; regression tests cover opt-in, preview-before-write, unknown-field dropping, and Wi-Fi credential boundaries.
- Deleted two pre-existing unredacted root diagnostic exports with user approval and added a [`.gitignore`](../.gitignore) pattern to exclude future report exports.
- Replaced the disabled production WebView CSP with a default-deny policy: only self-hosted UI assets and Tauri IPC are allowed; Vite HMR and its CSS injection allowance exist only in `devCsp`. A regression contract checks the production/dev split.
- Removed renderer filesystem-plugin access entirely. All seven frontend exports now go through a bounded Rust command that opens its own native Save dialog and accepts no renderer-supplied target path; a contract guards the boundary.
- Restricted startup-folder file moves to canonical direct children of the user/common Startup or AeroTune disabled folder, with regular-file/extension/ADS/symlink checks and an explicit admin check for common Startup.
- Bound recycle-bin deletion to short-lived server-held scan grants: disk results authorize only returned large files, duplicate results only verified visible members, file snapshots are rechecked, retries are consumed, and duplicate deletion must leave a visible copy.
- Moved configuration import into a pathless Rust command: the native JSON picker, bounded local-file read, validation, and apply stay server-side; cancellation is a no-op and dialog/read failures remain errors.
- Restricted disk scans to backend-resolved user-profile/system-drive presets; duplicate scanning now uses a Rust-owned native folder picker and bounded, expiring random handles for rescans. Removed renderer-side dialog-open permission and its unused JS package.
- Hardened `open_path`: reject UNC/device/ADS and relative paths before filesystem probes, reject mapped/network or reparse-point paths, canonicalize existing local files/directories, then invoke Explorer with the validated target. Its launcher and the settings-page command resolve Explorer from the Windows directory, not PATH.
- The shared child-process runner now resolves PowerShell and commonly used Windows tools (including `takeown`, `icacls`, `cmd`, `powercfg`, `ipconfig`, `defrag`, `schtasks`, `dism`, `compact`, and `vssadmin`) under the OS-reported system directory, verifies ordinary non-reparse executables, and fails closed for unknown names; this removes current-directory/PATH lookup from these command paths.

## General-availability blockers

1. **Signed distribution:** a Tauri Minisign keypair is configured in the protected GitHub release environment; create an offline backup and document rotation before general availability. Authenticode remains separate and optional; without it UAC may show Unknown publisher.
2. **Updater safety:** the owner authorized v1.5.10/v1.5.11 early access with release gates enabled. The v1.5.10 public bootstrap is installed and reports version 1.5.10; the v1.5.11 in-app GitHub update is pending. General availability remains blocked pending live update/system-proxy acceptance and UAC cancellation, concurrent-launch, interruption, and repair testing. The standard Tauri path has no AeroTune crash-safe rollback. See [UPDATER.md](UPDATER.md) and [UPDATER_RELEASE_BLOCKERS.md](UPDATER_RELEASE_BLOCKERS.md).
3. **Release evidence:** the early-access [Windows release workflow](../.github/workflows/release-windows.yml) is authorized only from clean, tagged `main` commits. Retain logs and complete installer install/upgrade/uninstall, standard-user/UAC, interruption/repair, and clean-machine tests in disposable VMs using the [install/uninstall acceptance matrix](INSTALL_UNINSTALL_ACCEPTANCE.md) before GA. The hosted image is still updated by GitHub within the `windows-2025` OS-generation label.
4. **Privacy:** review [DATA_PRIVACY_INVENTORY.md](DATA_PRIVACY_INVENTORY.md), publish the user-facing notice and verified data-retention/deletion/uninstall guidance, and validate local retention/telemetry behavior. The uninstall retention policy and manual cleanup steps are not yet verified; see the [VM acceptance matrix](INSTALL_UNINSTALL_ACCEPTANCE.md). Diagnostic preview/redaction is implemented and the discovered root exports were deleted; Settings now presents a concise local-data/export/uninstall summary, a source-based data-category/retention disclosure, and a limited, user-confirmed WebView history removal for five named keys; that is not a full data wipe or a legal privacy notice. Inspect any future release staging area separately.
5. **Accessibility:** test with Narrator and keyboard-only navigation, high contrast/forced colors, text scaling/200% zoom, and contrast tooling; fix all actionable failures rather than relying only on source contracts. The stylesheet now maps key surfaces, gradient text/buttons, and keyboard focus to forced-colors system colors. Compact game/developer/power-mode, GPU/EPP, scheduled-task, disk/CompactOS/memory-compression, and restore-point error alerts now wrap messages and keep retry controls reachable. Network-adapter read failures clear the selected target and keep stale rows read-only with inline retry/pending feedback; partial NIC/TCP reads preserve data for viewing but disable writes until a successful refresh. Network preference changes are serialized, show pending feedback, and re-read state after each attempt. Responsive source contracts cover these cases. These source-level safeguards do not replace Windows UI acceptance.
6. **Startup recommendations:** the UI distinguishes unique exact-path Event 101 observations from name-only heuristics, which remain non-measured. The startup-item table now discloses its covered/excluded sources and shows bounded embedded-Authenticode status plus the primary signer certificate subject when Windows exposes it; unsupported/ambiguous paths remain Unknown. This is informational, not a safety verdict: directory signatures are not checked and no online revocation check is performed. Release remains blocked until source coverage and signer display are accepted on disposable Windows VMs and the remaining startup-source inventory is reviewed.
7. **Operational support:** publish supported Windows versions, minimum requirements, uninstall/data-retention behavior, known limitations, recovery instructions, and a security/contact route.
8. **Source baseline:** on 2026-10-31 the project owner confirmed the current workspace source is the authoritative project version and clarified that an earlier assistant accidentally deleted/overwrote `lib.rs` without restoring it; the earlier assistant-generated note claiming the file was reconstructed from fragments was erroneous. The owner-confirmed current tree is the release baseline; freeze it in a versioned commit before building. The reviewed `lib.rs` SHA checkpoint is only a one-file integrity check, not a repository-tree digest; see the [provenance review](LIB_RS_PROVENANCE_REVIEW.md). This source-owner confirmation resolves the need for an external source baseline, but does not establish the other release evidence or GA readiness: signed distribution, hosted CI for the release commit, and Windows VM acceptance remain outstanding.
9. **Command-side path authorization:** configuration import owns selection, bounded read, validation, and apply inside Rust. Disk scans accept only named user-profile/system-drive presets resolved by Rust; duplicate scans use a Rust-owned folder picker and short-lived random selection handles, not renderer paths. Recycle-bin commands require a separate scan-result grant and preserve one visible duplicate per group. `open_path` rejects UNC/device/ADS and relative input before filesystem probes, rejects network/reparse-point targets, and canonicalizes local files/directories before Explorer. These measures constrain paths but do not prove human intent against a compromised renderer; assess trusted native confirmation for destructive actions. In particular, `remove_residual` now requires an admin token, validates a fixed allowlist, rechecks the root is not a reparse point, and displays a native warning/OK-Cancel dialog before running its recursive takeown/ACL/delete chain. Permanent `clean_junk` deletions and empty-recycle-bin requests now also require a backend Windows system dialog with Cancel as the default; cancellation performs no destructive action and the UI invalidates/reloads the one-use preview. Canonical cleanup paths are deduplicated across selected categories so the native count and byte total match the single-use plan. Source tests cover cancellation gating, but dialog behavior, compromised-renderer intent, and remaining destructive paths still require disposable-VM/security review. The listing scan is single-flight and uses the same no-follow walker with a 250,000-entry cap and 30-second aggregate elapsed budget checked between filesystem entries; incomplete roots remain visible with unknown size and deletion disabled. The delete preflight checks every descendant without following reparse points, rejects files with multiple Windows-reported hard links before recursive ownership/ACL changes, and fails closed on metadata/read errors, more than 1,000,000 entries, or a 120-second elapsed budget between filesystem entries (individual OS calls are not cancellable); `takeown`/`icacls` errors abort before deletion, and the root is rechecked before `rd`. Review concurrent filesystem races and validate this fail-closed behavior on a disposable Windows VM before GA; assess native-prompt sufficiency against compromised-renderer intent. Startup moves are confined to supported regular direct children of trusted directories, with admin checks for common Startup. `set_task_state` now repeats the enumerator's `\\Microsoft*` exclusion in Rust and rejects malformed folder/name components before `schtasks`. Continue Rust tests for path-taking commands; Tauri plugin capabilities do not authorize application-defined commands.

10. **Service modification scope:** startup-type changes require a readable service `ImagePath` that resolves to a regular, non-reparse executable outside the OS-reported Windows directory and under a Windows-known Program Files root. Native handle-based ACL checks cover that executable and every parent through the volume root; only SYSTEM, Administrators, and TrustedInstaller may own the path or receive file-write, add-file, delete-child, DACL, or ownership rights. The standard volume-root AddSubdirectory-only ACE is allowed because it cannot replace existing Program Files entries; unreadable DACLs and unsupported ACE forms fail closed. The configured account is cross-checked between CIM and the service registry for listing, then re-read from the SCM with `QueryServiceConfigW` and compared with the registry `ObjectName` immediately before mutation and undo. Only non-interactive Win32 own/share services with LocalSystem, LocalService, NetworkService, or the matching `NT SERVICE\<service>` virtual account are allowed; a NULL SCM account maps to LocalSystem only for those Win32 types. Driver, interactive, unreviewed custom/domain identities, and unsupported service types remain read-only. Service writes and undo open only an existing `Services\<name>` key instead of recreating it if a concurrent uninstall removes it. The `Start` and `DelayedAutostart` writes share one journal group and a failure in the second write triggers rollback of the first; rollback conflicts remain visible. Service-list read failures preserve the last snapshot as explicitly stale/read-only, disable startup edits and CSV export, and offer retry; source checks do not replace VM state/error acceptance. This is not Authenticode publisher verification, and ACL checking is not atomic with later service/configuration activity. Default Program Files ACL parsing passed on this host; test representative OEM/software services, supported Windows versions, and ACL/path races in disposable VMs before GA.

11. **Undo durability:** registry setters/deletes persist write-ahead snapshots before mutation; PowerSaver manual selection and adaptive plan changes persist write-ahead restore intent; scenario-mode groups now compensate earlier steps on failure; scenario and manual EPP writes persist pre-write snapshots and verify the written/restored values. TCP receive-window changes now fail closed unless the queried prior level is recognized by the journal restore allowlist, so journal-save rollback receives a restorable snapshot. Scenario mode labels now use atomic writes; a failed manual label write rolls back the just-applied journal group, and adaptive label-write errors are surfaced. Screen-brightness restoration remains outside the AutoState lock, prevents duplicate queued restores, exit now drains the brightness worker before reading the recovery snapshot (and retains the snapshot if the drain cannot be confirmed), while baseline shutdown reports pending recovery until a retry re-verifies the worker result; the engine page exposes a retry alert for unconfirmed brightness snapshots and a polite 30-second status when it preserves a diverged live value; failed writes retain their snapshot with bounded backoff; an atomic pre-dim brightness snapshot is retained on disk; out-of-range WMI readings are rejected before snapshot creation; recovery after successful or failed/partial dim writes, plus startup and exit recovery, re-reads and compares the live value before a conditional WMI write in one bounded PowerShell invocation (narrowing, but not eliminating, the native race); if the value diverges, it preserves it and clears the stale snapshot without writing; unreadable values or failed recovery retain the snapshot for retry. Adaptive baseline restore failures now propagate through disable/autopilot/config-import commands, retain an in-session retry state and expose an explicit retry path; the live baseline is not persisted across process exit, so post-restart recovery must use persisted journal entries. Focused source tests still do not replace disposable-VM checks of real `powercfg` partial failure, EPP support, and rollback behavior. Those paths serialize through the journal lock (including same-plan no-op checks), recheck the expected active GUID immediately before invoking `powercfg`, and verify the resulting active plan; bound undo is a no-op if the old plan is already active and rejects third-party state. Legacy plan records without an applied GUID are only accepted as no-ops when the old plan is already active; otherwise they fail closed to avoid overwriting an unverified external change. The check-to-process interval is still non-atomic against external processes. Snapshot-aware post-command records propagate persistence errors and attempt guarded compensation. DNS undo now checks the current applied state and, after a partial write failure, compensates only from known intermediate reset/IPv4 states; unexpected concurrent changes are not overwritten and compensation failure keeps the journal record. `Revert::None` operations cannot be safely compensated after completion; on journal failure they now return an explicit “operation may have completed” error, so keep those operations visibly non-reversible and validate their failure UX. `Journal::load` now distinguishes a missing file from unreadable, malformed, or oversized history; unhealthy files are preserved and journal-based mutations/recovery are blocked. Settings shows the IPC health error and disables actions based on stale snapshots. Retry re-reads an existing file only after it parses successfully; a missing file alone is not treated as recovery. Settings now offers a retry-first, preserve-and-restore guidance panel; if a last-good list remains visible, filtered CSV/JSON exports preserve descriptions but not undo values. There is still no in-app repair/quarantine flow, so preserve the original and use only a trusted copy before retrying. Validate the guidance under ACL/disk failures. Atomic file replacement still does not guarantee survival of hardware power loss.

## Release rule

A green local `pnpm run check:release` proves the checked local tests/build steps pass; it does **not** prove signed distribution, Windows UI accessibility, clean-machine compatibility, UAC behavior, update integrity, or repair after an interrupted installation. Do not enable GitHub updater acceptance gates based on CI alone.
